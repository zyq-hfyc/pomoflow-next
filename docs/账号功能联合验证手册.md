# P1d 账号功能联合验证手册(桌面端 ↔ 服务器端)

> **目标**:重新构建桌面端与服务端 → 部署到 VMware Ubuntu → 联合验证
> **账号全部功能**:注册(邮箱/账号密码)、登录、找回密码、改密码、设备管理、
> 头像上传/移除、个性签名、改用户名、换绑邮箱、账号注销(15 天冷静期)、
> 数据导出、最近登录记录、机型识别、顶栏头像。
>
> **适用现状**:VM 上已跑过旧版 sync-server(P1a,静态 Token 时代);Windows
> 开发机工具链齐全(cargo-zigbuild / Node / npm 已装)。
>
> **预计耗时**:20-30 分钟(构建约 15 分钟 + 部署操作 5 分钟 + 验证 10 分钟)。
>
> **全程三条铁律**:
> 1. **先部服务端,再装桌面端**(EntityKind 升级顺序,旧服务端会拒绝新客户端);
> 2. **账号只在第一台设备注册一次**,其余设备一律"登录"(注册第二账号会因数据
>    归属不一致被拒);
> 3. **改任何 .env 后必须重启容器**才生效。

## B. 服务器端部署(VMware Ubuntu 上执行)

### B1. 上传部署包(Windows 执行)

```bash
# scp 传到 VM 的 /home/yongchao(固定部署位置);<日期> 换成 A2 输出的日期
scp artifacts/pomoflow-sync-deploy-<日期>.tar.gz yongchao@<VM的IP>:/home/yongchao/
```

- **预期**:进度条走完无报错(约几秒,6-7MB)。

### B2. 解压覆盖 + 配置 .env(VM 上执行)

```bash
# ① 解压覆盖旧目录(tar 覆盖解压,旧 .env 与数据库卷都不受影响)
cd /home/yongchao && tar -xzf pomoflow-sync-deploy-<日期>.tar.gz

# ② 进入部署目录(后续 VM 命令都在这里)
cd pomoflow-next/services/sync-server

# ③ 确认 .env 还在(升级解压不会动它;没有就 cp .env.example .env)
ls -la .env
```

> 📌 **路径说明**:部署位置固定为 `/home/yongchao`(解压后即
> `/home/yongchao/pomoflow-next/services/sync-server`,后续 VM 命令都在这里)。
> docker compose 按目录识别项目 —— 历史上若从别的目录起过容器,先把旧项目
> `docker compose down` 掉再在新位置起,避免两套并存。

### B3. 生成密钥并写入 .env(★ 本手册核心步骤)

```bash
# ① 生成 JWT_SECRET(启用账号体系的开关)—— 复制输出的 64 位十六进制串
openssl rand -hex 32

# ② 再生成一个 CODE_PEPPER(验证码摘要盐,建议与 JWT_SECRET 不同)—— 同样复制
openssl rand -hex 32

# ③ 编辑 .env,在文件末尾追加两行(粘贴上面两个值;井号开头的示例行可删)
#    SMTP 段本次先【不配置】= 日志模式,验证码打在服务端日志里,联调最省事
nano .env
```

追加后的 `.env` 末尾应类似:

```ini
JWT_SECRET=a1b2c3...e4f5(64 字符)
CODE_PEPPER=1122...3344(64 字符)
```

| 字段 | 作用 | 本次 |
|------|------|------|
| `JWT_SECRET` | JWT 签名密钥;**不设 = 无账号功能**(注册登录全 503) | ✅ 必填 |
| `CODE_PEPPER` | 验证码摘要盐(不设回落 JWT_SECRET,日志告警) | ✅ 建议 |
| `SMTP_*` 五项 | 真发信;不设 = 日志模式(码在 `docker logs` 里) | ⏭ 暂不配 |

### B4. 重启并核验

```bash
# ① 重建并重启(预编译路径:只 COPY 二进制,秒级;启动时自动建新表)
docker compose up -d --build

# ② 两容器状态:postgres 应为 Up (healthy),sync-server 为 Up
docker compose ps

# ③ 健康检查:应返回 {"ok":true,...}
curl http://127.0.0.1:8080/healthz

# ④ 关键:启动日志确认账号体系与邮件模式都已生效
#    预期一行含 auth=jwt+static 且 mail=log
docker compose logs sync-server 2>&1 | grep -E "auth=|mail="

# ⑤ 新表已建:应列出 users / auth_identities / email_codes / refresh_tokens
docker compose exec postgres psql -U pomoflow -d pomoflow -c "\dt"
```

### B5. 发码冒烟(日志模式取码方法,后面验证全靠它)

```bash
# ① 触发一次发码(邮箱随意;预期返回 {"ok":true,"expires_in":600})
curl -s -H "Content-Type: application/json" \
     -d '{"email":"smoke@test.local","purpose":"register"}' \
     http://127.0.0.1:8080/v1/auth/email/send-code

# ② 立刻再发一次:预期 429 + retry_after_secs(频控生效,60 秒窗口)
curl -s -H "Content-Type: application/json" \
     -d '{"email":"smoke@test.local","purpose":"register"}' \
     http://127.0.0.1:8080/v1/auth/email/send-code

# ③ 从日志取验证码([mail:log-mode] 行的下一行"你的验证码是:XXXXXX",-A 2 把后两行带出来)
docker compose logs sync-server 2>&1 | grep -A 2 "mail:log-mode"
```

> 以后每次"发送验证码"后,都用 ③ 这条命令取码(日志模式)。

## D. 联合验证清单(逐步执行,每步有预期)

### D1. 基础连通(沿用旧配置的跳过)

1. 设置 → 数据同步:服务器地址 `http://<VM的IP>:8080`、
   访问令牌 = .env 的 `SYNC_TOKEN` → 保存配置;
2. 点**立即同步** → 预期 `完成:推送 N 条,拉取 X 条`(数据已在云上的话 N 很小);
3. 账号区显示"未登录" + 「登录 / 注册 →」按钮(收敛后的新入口)。

### D2. 首账号注册(★ 关键:自动并入存量数据)

1. 设置 → **账号** tab → 认证卡片 → **注册** → **邮箱注册**;
2. 输入你的真实邮箱 → 点**发送验证码**(按钮进入 60s 倒计时);
3. VM 上执行取码:
   ```bash
   docker compose logs sync-server 2>&1 | grep -A 2 "mail:log-mode"
   ```
4. 输入 6 位码 + 设置密码(强度条会动)→ 确认密码 → **注册**;
5. **预期**:卡片切换为"账号管理中心"(左侧你的昵称+邮箱,四区导航);
6. **采纳验证**(VM 上):
   ```bash
   # 预期:恰好一行,且 id 列 = .env 里的 SYNC_USER_ID(存量数据已并入该账号)
   docker compose exec postgres psql -U pomoflow -d pomoflow \
     -c "SELECT id, username, email FROM users;"
   ```

> ⚠️ 若注册时报"该账号(...)与本机数据归属不一致":注册请求没带运维静态令牌
> (本手册配套的新桌面版已修复)或 users 表里已有别的账号。处置:
>
> ```bash
> # ① VM 上清掉错误账号(单账号阶段安全;同步数据 snapshots/changelog 不动)
> docker compose exec postgres psql -U pomoflow -d pomoflow \
>   -c "DELETE FROM refresh_tokens; DELETE FROM auth_identities; DELETE FROM users;"
> ```
>
> ② 桌面端改走「注册 → **账号注册**(用户名+密码)」—— 该路径带运维令牌,
>    会正确采纳 SYNC_USER_ID;
> ③ 进账号中心 → 个人资料 → **绑定邮箱**(发码+当前密码),邮箱能力齐活,
>    之后 D3 邮箱登录即可用。
>
> 若 users 表里是此前测试留下的账号,同样用 ① 清理后重来。

### D3. 邮箱登录(退出重进)

1. 账号中心左下 **退出登录** → 回到认证卡片;
2. **登录** → **邮箱登录** → 邮箱 + 密码 → 登录 → 预期回到账号中心;
3. **错误路径**:故意输错密码 → 预期统一报"邮箱或密码错误"(不泄露哪个错)。

### D4. 找回密码(三步流 + 全端踢出验证)

1. 认证卡片 → **找回密码** tab(三步指示器亮第 ① 步);
2. 输入绑定邮箱 → 发送验证码 → VM 取码 → "下一步"进第 ② 步;
3. 输新密码(两次一致)→ **确认重置** → 第 ③ 步成功页(明示所有设备已下线);
4. **踢出验证**(VM 上,预期 revoked 行数 ≥ 注册以来的会话数):
   ```bash
   docker compose exec postgres psql -U pomoflow -d pomoflow \
     -c "SELECT COUNT(*) FROM refresh_tokens WHERE revoked_ms IS NOT NULL;"
   ```
5. 返回登录,用**新密码**登录成功 = 闭环。

### D5. 账号管理五区(全功能)

| 区 | 操作 | 预期 |
|----|------|------|
| 顶栏 | 观察导航栏最左侧 | **登录后番茄图标+PomoFlow 变为用户头像**(无头像=首字母),点击直达账号页;退出后变回番茄 |
| 个人资料 | **上传头像**(选 JPG/PNG ≤2MB) | 资料页 64px 圆 + 左菜单头部 + **顶栏头像**三处同步显示图片 |
| 个人资料 | **移除头像** | 三处回落为首字母 |
| 个人资料 | 修改昵称 → 保存 | 左菜单头部昵称即时更新 |
| 个人资料 | **个性签名** → 修改(弹窗 50 字计数) | 签名行更新(在邮箱行下方) |
| 个人资料 | 修改用户名(需当前密码) | 提示"其他设备需重新登录";**本机不掉线** |
| 个人资料 | 修改邮箱(换绑) | 新邮箱验证码 + 当前密码;成功后"已验证"徽章 |
| 安全设置 | 修改密码(旧+新+强度条) | 成功提示"其他设备已全部下线" |
| 第三方账号 | 微信行 | 显示"待资质"徽标(不可点,符合预期) |
| 登录设备 | 刷新/单台下线/退出其他 | 列表实时变化;"本机"行无下线按钮 |
| 登录设备 | **设备名识别** | 本机显示真实机型(如 "HUAWEI MateBook");旧会话显示老格式(不追溯) |
| 登录设备 | **最近登录记录**卡 | 每次登录/注册留一行:时间/设备/IP/方式/成败;失败行悬停可看原因 |
| 账号注销 | **导出数据** → 导出 | 保存 pomoflow-backup-<日期>.json(含 profile + 全部云端快照) |
| 账号注销 | 申请注销(验证码+当前密码+输入"注销账号"+勾选) | 黄色横幅"申请中,将于 <15 天后日期>";**撤销注销**(密码)后恢复正常 |

> 注销生效语义(安全设计,非 bug):申请后其他设备全部下线、保留本机可撤销;
> 15 天内不撤销,每日维护任务将**级联删除云端全部数据**(含同步快照)后账号消失。
> 验证注销功能建议:申请 → 看横幅 → 撤销 即可,**不要真等 15 天**。
> psql 侧核对:`SELECT deletion_requested_ms FROM users;`(非空=申请中)。

### D6. 回归:同步链路仍正常

设置 → 数据同步 → **立即同步** → 预期正常完成(此时走的是账号 JWT,
401 时自动刷新,无需人工干预)。

## E. 常见故障排查

| 现象 | 原因 | 处置 |
|------|------|------|
| 桌面构建报 `failed to remove file ...exe` | PomoFlow 还在运行 | 托盘退出后重跑 C2 |
| 注册/登录报"服务器返回 503"或 JWT_SECRET 未配置 | B3 没做或 B4 没重启 | 补 .env 后 `docker compose up -d` |
| 重启后日志仍是 `auth=static` | compose 未转发变量(旧包 bug,已修复)或 .env 未保存 | 确认用含 P1d 转发的新 compose;`docker compose config` 里应能看到 JWT_SECRET |
| 收不到验证码 | 日志模式下码在服务端日志,不在邮箱 | B5-③ 命令取码;配了 SMTP 才查邮箱/垃圾箱 |
| 发码报 429 | 频控(同邮箱 60s / 5 每时 / 10 每天) | 等 `retry_after_secs` 或换邮箱 |
| 注册报"归属不一致" | 旧版桌面邮箱注册未带运维令牌(已修复)/ users 表已有账号 / SYNC_USER_ID 与本机不符 | 见 D2 ⚠️;核对 .env 的 SYNC_USER_ID |
| 验证码总不对 | 超过 10 分钟 / 已用过 / 错 5 次作废 | 重新发送新码 |
| 桌面连不上服务器 | VM 桥接/防火墙/IP 变化 | Windows 浏览器测 `http://<IP>:8080/healthz` |
| 立即同步报 401 | 静态令牌与 .env 不一致,且未登录账号 | 核对 SYNC_TOKEN,或先完成 D2 登录 |
