## Context(为什么做)

V2 桌面端(Tauri 2,0.2.0)与 Android 端(Flutter,0.2.0+2012)已发布,但没有任何更新机制,
新版本只能靠用户手动去官网/GitHub 重新下载。用户要求加「检查更新」:有新功能时可更新安装。
桌面端明确要**腾讯系体验**:应用内检测 → 后台静默下载(带进度)→ 下载完提示 → 用户决定
立即重启升级/稍后 → 升级全程无安装向导。更新源走**自建 sync-server**(ADR-013 分发面已存在)。
范围:**V2 桌面 + V2 Android**(V1 老线本次不做)。

## 原理详解(实现前必读的依赖条件)

### 通用四环节
1. **版本标识**:桌面 = tauri.conf/Cargo 的 semver;Android = versionCode(单调递增整数,2012)+ versionName(展示)
2. **版本发现**:客户端请求稳定的「更新清单」端点 → 与本地版本比较(semver / versionCode)。依赖:可达的清单 URL、比较规则
3. **分发**:下载安装包。依赖:稳定下载 URL、sha256 完整性校验、签名校验(防篡改)
4. **安装**:替换旧版本。两个硬约束:
   - **Windows 文件锁**:运行中的 exe 无法自我替换 → 替换必须由**另一个进程**完成(腾讯用自研升级进程;Tauri 用静默 NSIS `/S` 安装器,等主程序退出后覆盖文件再重启——效果等同,无需自研)
   - **Android 签名一致性**:更新 APK 必须与已装应用同 keystore 签名,否则系统拒绝覆盖安装(已有正式 keystore ✓);且 versionCode 必须更大;Android 8+ 需 `REQUEST_INSTALL_PACKAGES` 权限 + 用户授予「安装未知应用」

### 腾讯式体验 = Tauri 官方 updater 插件的编排
`tauri-plugin-updater` 原理:编译期内嵌 minisign 公钥 → 构建期私钥对安装包签名产出 `.sig` →
运行期插件请求配置的 endpoint(Tauri dynamic JSON:`{version, notes, pub_date, platforms:{"windows-x86_64":{signature, url}}}`)→
semver 比对 → `download()` 后台下载(进度事件)→ 验签 → `install()` = 退出 → 静默 NSIS → relaunch。
「先静默下完再问用户装不装」正是腾讯模式,流程由我们在应用层编排。

### iOS
Windows 主机无法构建签名工具链,排除(与仓库现状一致,登记不阻塞)。

## 现状盘点(已核实)

- sync-server `release_handlers.rs`(ADR-013):管理面 `/internal/releases*`(原始字节流上传 + 滚动 sha256 + publish/unpublish)、
  公开面 `/api/public/releases`、`/api/public/releases/latest`、`/api/public/download/{asset_id}`(无鉴权);
  PLATFORMS 含 windows/linux/mac/android;资产表已有 filename/size_bytes/sha256
- 桌面:tauri.conf.json 0.2.0、无 updater 插件(Cargo 只有 notification/autostart/dialog)、
  release.yml 三平台 tauri-action → GitHub Release 草稿、受管版烘焙 `POMOFLOW_DEFAULT_SERVER_URL`
- Android:pubspec `0.2.0+2012`、keystore.properties 正式签名、Manifest 仅 INTERNET/POST_NOTIFICATIONS/RECEIVE_BOOT_COMPLETED、
  HTTP 栈 = `http: ^1.2.0`(api_client.dart 已有服务器地址配置)、设置页 `lib/pages/settings_page.dart`
- 两端 UI 均未展示当前版本号

## 实施

### A. 服务端:更新清单端点(services/sync-server)

1. 新 `src/update_handlers.rs`(或并入 release_handlers.rs):
   - `GET /api/public/update-manifest/{target}`,target ∈ `windows-x86_64` / `linux-x86_64` / `darwin-aarch64` / `android`
   - 桌面三靶:返回 **Tauri dynamic JSON**(从最新已发布 release + 该平台资产 + 伴生 `.sig` 资产拼装;url 指向 `/api/public/download/{asset_id}`)
   - android:返回 `{version, versionCode(int,从 version 解析), notes, url, size, sha256}`
   - 无已发布版本 → 404(客户端视为「已是最新」);资产缺 `.sig` 伴生 → 该平台不出现在 platforms 里(不能给出验签不过的更新)
   - 约定:签名文件作为**伴生资产上传**(同名 + `.sig`),端点按文件名规则查找
2. 单测:结构拼装 / 无版本 / 缺 sig 降级

### B. 桌面端(apps/desktop)

3. **一次性密钥**:`cargo tauri signer generate -w ~/.tauri/pomoflow.key` →
   私钥进 GitHub Secrets(`TAURI_SIGNING_PRIVATE_KEY`;密码为空无需 PASSWORD 项),
   **公钥**写进 tauri.conf.json(私钥丢失 = 无法给存量用户推更新,必须备份)
4. `Cargo.toml` += `tauri-plugin-updater`、`tauri-plugin-process`;`src/lib.rs` 注册两插件;
   `capabilities/default.json` 加 `updater:default`、`process:allow-restart`
5. `tauri.conf.json`:
   - `bundle.createUpdaterArtifacts: true`
   - `plugins.updater { endpoints: [dev 占位], pubkey, windows: { installMode: "passive" } }`
     (生产端点由 release.yml `--config` 注入,地址不入仓)
6. UI:新 `ui/src/components/Settings/UpdateSetting.svelte` + 挂进 SettingsPage:
   - 启动静默检查(设置开关,默认开)+ 手动检查按钮
   - 腾讯式状态机:`idle→checking→(已是最新|发现新版 vX+notes)→downloading(进度)→ready(Toast)→重启更新(install)/稍后`
7. i18n zh/en 成对
8. `release.yml`:签名 env + 端点注入 + 产物/.sig 入库 sync-server(draft,人工 publish)

### C. Android(apps/mobile)

9. `pubspec.yaml` += open_filex / package_info_plus / crypto;`AndroidManifest.xml` +=
   `REQUEST_INSTALL_PACKAGES`
10. 新 `lib/services/update_service.dart`:清单检查(versionCode 严格大于 buildNumber)、
    流式下载(进度 + sha256 校验 + 可取消)、OpenFilex 拉起系统安装器
11. `settings_page.dart` 关于区加「检查更新」卡片(版本号取 PackageInfo)
12. 测试:UpdateService 单测(FakeClient + 临时目录)

## 验证

2. 桌面端到端:装 0.2.0 → 挂 v0.2.1 → 应用内检查 → 静默下载 → 重启升级,全程无向导
3. Android 端到端:真机 0.2.0(2012)→ 挂 v0.2.1(2013)→ 覆盖安装成功

5. 全量门禁:cargo fmt/check/test + push 后 CI

## 依赖与风险(登记)

- 生产服务器必须可达(受管版已烘焙地址)
- CI 自动入库依赖 `INTERNAL_SERVICE_TOKEN` secret
- **签名私钥是命根子**:丢失即失去存量用户更新通道
- 灰度/强制更新:manifest 可留 `mandatory` 字段,本次不做(YAGNI)
- GitHub Release 草稿产线保留;sync-server 入库是新增一步,两套资产短期并存
